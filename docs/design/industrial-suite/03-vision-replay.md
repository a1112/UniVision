# VisionReplay 回放与对比设计

版本：0.1.0-draft  |  日期：2026-09-23  |  状态：拟议设计

目标：在 `a1112/UniVision` 单仓库内作为可选扩展落地。本文不代表已实现或已验收。

## 13  VisionReplay：重现过程而不只播放图片

### 产品目标与首版

把一次检测的输入、时间关系、参数、标定、算法结果与运行环境组织为可验证会话。第一版支持文件/合成数据录制、会话浏览、播放/暂停/定位、对同一输入重跑两组已登记算法配置，并导出差异证据。

| 对象 | 职责 |
| --- | --- |
| Recorder | 位于共享 recording 模块，只实现一次；可由流接收端或离线流程调用 |
| Session Catalog | 读取清单、完整性与统计，不自动扫描任意磁盘或下载外部数据 |
| ReplayEngine | 基于指定时钟/序号重放，协调 seek 与暂停，不操作实体设备 |
| Comparator | 按版本化规则比较两个 RunManifest 的可比输出 |
| Review UI | 时间轴、多路画面、叠加、差异与异常定位 |

### 会话必须装下什么

原始帧及必要元数据、触发/缺口事件、参数快照、标定引用、时钟映射、图与节点版本、模型摘要、环境清单以及原始结果。支持只录输入的轻量会话，但界面必须说明未记录的部分。

raw-device-code 原样保留；派生毫米图、裁剪图与推理结果保存在 derived/run-id 下，不改写原始帧。只提供截图的视频录像不足以作为测量回放输入。

> 最小闭环：导入一段数据 → 定位某帧 → 选择两版参数 → 重跑 → 解释差异 → 导出含来源的报告。

不做普通素材库、客户数据云盘、现场控制台或“自动生成合格结论”。原始数据、人工标注与算法结果各自版本化。

## 14  VisionReplay：录制格式与崩溃恢复

建议 MCAP 作为时间序列容器，目录清单负责会话级完整性和来源。MCAP 已定义带时间戳的消息、通道、块和索引；不是网络交付协议，也不是开箱即用的 UniVision 业务格式。[S6]

```text
session-id/
  session.json                 # 版本化会话清单
  segments/000001.mcap          # 已关闭的不可变段
  segments/000002.mcap.partial  # 未提交尾段
  artifacts/calibration/...    # 标定、参数等小制品
  derived/run-id/...           # 重跑结果
  reviews/revision-id/...      # 人工备注与评审
```

草案 MCAP message_encoding 为 univision.frame.v1：uint32 大端 metadata_length + UTF-8 FrameEnvelope JSON + 原始二进制载荷。通道 schema 说明组合编码；其他查看器需要相应解码器，不能宣称天然兼容所有 MCAP 工具。

初始记录参数建议：8 MiB 目标 chunk、单段 4 GiB 或 60 秒先到者关闭；已 JPEG 编码的数据默认不二次压缩。块压缩、文件摘要和段大小必须以磁盘压力测试决定。

### 时间与顺序

log_time 写记录时的 UTC ns；publish_time 仅在源时钟已可靠映射到同一纪元时使用，否则等于 log_time。设备原始 tick 与映射质量留在消息元数据，不能硬塞进同一时轴。[S6]

定位可按记录时间、已映射采集时间或序号。时钟跳变显示分段；仅当映射质量允许时做跨路时间对齐。帧因果/批次优先使用显式触发或序号关系。

### 关闭与恢复

清单只有在段关闭、校验并持久发布后登记。损坏尾段可恢复成带 recovered/partial 标记的新制品；保留原件。缺索引可扫描重建，但缺字节不能补成正常帧。报告恢复前后摘要、有效区间和损失范围。

## 15  VisionReplay：重放与版本比较

### 重放语义

播放速度是调度策略，不改变保存的采集时间。首版支持暂停、单步、跳转和 0.25×～4× 播放；数据读取和预览各用有界缓存。任意 seek 递增 generation，旧任务完成后不能覆盖新位置的视图或结果。

状态节点回放不能只移动文件游标。必须从检查点恢复其状态，或从会话起点/已声明的 warm-up 边界重新执行；未实现这条路径的节点不得宣称支持准确随机定位。

### 比较前先验证可比性

| 比较层 | 判断规则 |
| --- | --- |
| 输入一致 | 相同源/有效帧集合与输入摘要；缺口不同必须提示不可直接比较 |
| 几何一致 | 单位、坐标系、ROI、标定和变换一致，或存在显式可追溯变换 |
| 图像/矩阵 | 区分编码字节差异与解码数值差异；使用明确的绝对/相对容差和掩码 |
| 轮廓/测量 | 比较数值、有效点、拟合残差、标定和不确定度，不只比较“合格/不合格” |
| 检测框/分类（后续） | 登记匹配规则、IoU/阈值与类别版本；没有标注真值不报告准确率 |
| 运行环境 | 算法/模型/Provider/精度模式/种子/依赖变化必须进入比较报告 |

确定性等级建议为 bitwise、numeric-tolerance、statistical、not-reproducible。固定输入和 seed 不自动使所有 GPU 算法逐位确定；报告真实等级与已知非确定性。

### 证据输出

导出比较摘要、逐帧指标、异常索引、输入/参数/环境摘要与选择性的最小数据包。所有指标可追溯到帧 ID；未经许可的原始数据不随报告默认外发。人工标注不能覆盖算法原始结果。

## 16  VisionReplay：界面与验收

| 区域 | 界面与交互 |
| --- | --- |
| 左侧会话树 | 会话、数据源、标定、运行和评审；完整/恢复/损坏状态常驻 |
| 中央查看区 | 单路/四宫格、强度/深度/掩码图层、A/B 同步视图 |
| 底部时间轴 | 帧、触发、告警、缺口与映射 epoch；支持按序号定位 |
| 右侧证据栏 | 当前帧来源、时钟、单位、参数、标定与结果；可复制 ID |
| 比较抽屉 | 选择两个冻结的 run，不允许边运行边修改比较基线 |

### 关键异常文案

“缺少 120～127 帧，不能重现这一区间”“设备时钟未映射，当前仅按记录时间排列”“结果坐标系不一致，请指定变换”“尾段恢复成功：有效前缀，不是完整会话”。不以空白窗口替代错误。

### 首版验收

同一合成会话可顺序重放和随机定位；seek 后旧 generation 不能回写；损坏尾段不被当作完整数据；相同输入同确定性节点结果满足声明等级；非法外部路径被拒绝；只读原始数据不因重跑而改变摘要。

至少测试一条“时钟跳变 + 中间缺口 + 图版本变化”的会话，并导出有解释的差异报告。数据缺失时显示不可比，不能通过插值让报告看似正常。

### 性能建议

在固定合成基准集上测首次打开、索引读取、seek 到预览、单步与批量比较耗时。建议已索引本地会话的 seek-to-preview P95 目标 ≤500 ms，但需锁定文件大小、磁盘和预览尺寸；这是工程目标，不是已测结果。

后续再扩展跨会话搜索、状态节点检查点、多种第三方解码器。首版先保证一份会话确实能在无相机电脑上被正确解释。
